# レシピの形

[English](recipe_format.md)

レシピの形の、すべての説明です。レシピが受ける欄と、その値と、Vpmify がそれをどう読むかを書きます。レシピの書き方の案内は [recipe.ja.md](recipe.ja.md) にあります。

ここに書くのは、形の版 1（`"vpmifyFormat": 1`）です。

## ファイル

- レシピは UTF-8 の JSON のファイルです。先頭の BOM はあってもかまいません。
- URL から読むレシピは、`https` でだけ読み、大きさは 10 MiB までです。
- いちばん外側はオブジェクトで、これがレシピです。
- 欄の名前は、大文字と小文字を区別します。1 つのオブジェクトに同じ名前の欄が 2 回あると、エラーです。
- ここにない欄は無視するので、`$schema` や、覚え書きの欄を書いてもかまいません。書き違えた欄も、エラーにならずに無視されます。
- 欄の型が違う（真偽値の欄に文字列を書いた、など）と、エラーです。
- 「省略可」の欄は、書かなくてもかまいません。説明に断りがなければ、`null` と書くのは、書かないのと同じです。

## レシピ

いちばん外側のオブジェクトです。

- `vpmifyFormat`（整数、必須）: レシピを書いた形の版。これのない JSON は、レシピとして読みません。1 より小さいとエラーです。この Vpmify が読めるいちばん新しい版より大きいと、新しい Vpmify が要ると言って断ります。
- `id`（文字列、必須）: レシピの識別子。英小文字 `a-z`・数字 `0-9`・`.`・`_`・`-` でできていて、先頭は英小文字か数字です。レシピを書く人のドメインを逆さにした形（`com.example.univrm`）で書きます。この形かどうかは、Vpmify は確かめません。同じ `id` のレシピを取り込むと、前のものを置き換えます。
- `displayName`（文字列、必須）: 人が読む名前。空にはできません。`recipe add` と `recipe list` の JSON の結果（`--json`）に入ります。
- `url`（文字列、省略可）: レシピを公開している URL。レシピを読む人や道具のための欄で、Vpmify は読みません。
- `sources`（[ソース](#ソース)の配列、必須）: 1 つ以上。`null` の要素はエラーです。`packages` の `null` の要素も同じです。

1 つのレシピの中で、同じ名前のパッケージは 1 回しか書けません。ソースが違っても同じです。

## ソース

パッケージをどこから取るか。ほかにどの欄を受けるかは、`type` で決まります。

- `type`（文字列、必須）: `"npm"` か `"github"`。ほかの値はエラーです。

### npm のソース

npmjs や OpenUPM のような、npm と同じ形のレジストリです。

- `type`: `"npm"`
- `registry`（文字列、必須）: レジストリの URL。スキームが `https` で、ホストのあるもの。平文の `http` は断ります。
- `packages`（[パッケージ](#パッケージ)の配列、必須）: 1 つ以上。

npm のソースは `url`・`tagVersion`・`tags` を受けません。空でない値を書くとエラーです。

Vpmify は、パッケージごとに、レジストリのドキュメントを 1 回読みます。その `name` がパッケージの名前と違うと、ソースを読めません。版は、番号が [SemVer](#版) で、tarball があるときに読みます。ほかは外します。tarball の中の `package.json` は、`name` がパッケージの名前で、`version` が版の番号でなければならず、違うとその版は変換できません。

### github のソース

GitHub のリポジトリです。tag を版として読みます。

- `type`: `"github"`
- `url`（文字列、必須）: `https://github.com/<owner>/<repo>`。末尾の `.git` はあってもなくてもかまいません。スキームは `https`、ホストは `github.com` でなければなりません。ほかのホストは使えません。
- `tagVersion`（オブジェクト、省略可）: tag の名前から版を読む決まり（[tagVersion](#tagversion) を見てください）。書かないと、tag の名前の先頭の `v` か `V` を 1 つだけ落として、[SemVer](#版) として読みます。
- `tags`（[範囲](#範囲)、省略可）: 読む tag。tag の版の範囲です。書かないと、全部の tag。
- `packages`（[パッケージ](#パッケージ)の配列、必須）: 1 つ以上。

github のソースは `registry` を受けません。空でない値を書くとエラーです。

名前を版として読めない tag は、読みません。読む tag では、パッケージごとに、そのフォルダの `package.json` を読みます（[path と paths](#path-と-paths) を見てください）。

### tagVersion

- `match`（文字列、必須）: RE2 の書き方の正規表現（先読み・後方参照は使えません）。tag の名前の全体に合わなければなりません。合わない tag は読みません。
- `version`（文字列、必須）: `match` のグループから版を作るひな形。
  - `{N}` は、`match` の `N` 番目のグループです（`{0}` は名前の全体）。
  - `{N:0W}` は、`N` 番目のグループの左を 0 で埋めて `W` 桁にしたものです。`W` は 18 まで。
  - ほかの文字は、そのまま書かれます。`{` と `}` は文字として書けません。
  - `N` が `match` のグループの数より大きい `{N}` は、エラーです。

`match` に合った tag は、次のように読みます。

- 合わせに加わらなかったグループと、空の文字列に合ったグループは `0` です。
- 埋める桁 `W` より長いグループがあると、その tag は読みません。
- 結果の版の番号と、プレリリースの数の先頭の 0 は落とします。ビルドメタデータでは落としません。
- 結果が [SemVer](#版) でなければ、その tag は読みません。

例: `"match": "(\\d+)\\.(\\d+)\\.(\\d+)(?:\\.(\\d+))?"` と `"version": "{1}.{2}.{3}{4:03}"` では、tag `0.15.2.2` は 0.15.2002、tag `0.15.2` は 0.15.2000 です。tag `0.15.2.1000` は読みません。

## パッケージ

ソースから何を取り、どう直すか。

次の欄は、どのソースのパッケージも受けます。

- `name`（文字列、必須）: パッケージの名前。上流の `package.json` の `name` と同じでなければなりません。`/` と `\` を含めず、`.` と `..` にもできません。
- `versions`（[範囲](#範囲)、省略可）: 取る版。パッケージの版の範囲です。書かないと、全部の版。範囲の外の版は版の一覧に入らず、利用者が名指ししても取れません。範囲の中のプレリリースも版の一覧に入ります。いつ取るかは「[pull が版を選ぶ決まり](#pull-が版を選ぶ決まり)」にあります。
- `onDemand`（真偽値、省略可、既定は `false`）: `true` にすると、パッケージを名指ししない `pull` が、このパッケージを選びません。[依存](#依存の辿り方)としてと、利用者がパッケージかその版を名指ししたときには取ります。
- `overrides`（[オーバーライド](#オーバーライド)の配列、省略可）: `package.json` の直し。

次の欄は、github のソースのパッケージだけが受けます。npm のソースのパッケージに空でない値（`versionFromTag` は `false` でない値）を書くと、エラーです。

- `path`（文字列、省略可）: [path と paths](#path-と-paths) を見てください。
- `paths`（配列、省略可）: [path と paths](#path-と-paths) を見てください。
- `versionFromTag`（省略可）: [versionFromTag](#versionfromtag) を見てください。
- `overlays`（[overlay](#overlay) の配列、省略可）: パッケージのフォルダに入れる、ほかのリポジトリの中身。

github のソースのパッケージは、ある tag で次のときに読みません。フォルダに `package.json` がないとき、そのファイルが `name` と `version` が文字列で、`dependencies` があればそれが文字列のオブジェクトである JSON のオブジェクトでないとき、`name` が違うとき、`version` がないとき。tag の版を取らない（`versionFromTag` でない）なら、`version` も [SemVer](#版) でなければなりません。

### path と paths

リポジトリの中の、パッケージのフォルダ（`package.json` のあるフォルダ）。`path` か `paths` のどちらかを書きます。両方は書けません。

- `path`（フォルダ、省略可）: すべての tag でのフォルダ。書かないときと `""` は、リポジトリのルート。
- `paths`（オブジェクトの配列、省略可）: tag ごとのフォルダ。要素は次の欄を持ちます。
  - `tags`（[範囲](#範囲)、省略可）: 当てる tag。tag の版の範囲です。書かないと、全部の tag。
  - `path`（フォルダ、必須）: フォルダ。`""` はリポジトリのルートです。`path` のない要素はエラーです。

`paths` の範囲どうしは重なってはいけません。どちらも満たす版はないが、順に並べると接する範囲（`>1.0.0` と `<1.0.1-0` など）も、重なると数えます。どの範囲にも入らない tag では、そのパッケージを読みません。

フォルダは、名前を `/` でつないで書きます（`Assets/VRM` のように）。`\`、空の名前（`A//B`）、`.`、`..` は書けません。先頭と末尾の `/` は落とします。

### versionFromTag

パッケージの版を、`package.json` の `version` の代わりに、tag の版にします。Vpmify は、変換した `package.json` にその版を書きます。

- `true`: すべての tag で。
- `false` か、書かない: どの tag でもしない。
- `{ "tags": "<範囲>" }`: 版がこの範囲（tag の版の範囲）に入る tag で。ほかの tag では、`package.json` の版のままです。`tags` は必須で、`{}` や `""` はエラーです。

### overlay

ほかの GitHub のリポジトリのコミットの中身を、パッケージの空のフォルダに入れます。GitHub が出すアーカイブは、Git のサブモジュールを空のフォルダにして外すので、それを埋めます。

- `tags`（[範囲](#範囲)、省略可）: 当てる tag。tag の版の範囲です。書かないと、全部の tag。
- `path`（[フォルダ](#path-と-paths)、必須）: 埋めるフォルダ。パッケージのフォルダから見たパスです（リポジトリのルートからではありません）。パッケージのフォルダそのもの（`""`）にはできません。
- `url`（文字列、必須）: 中身を取るリポジトリ。[github のソース](#github-のソース)の `url` と同じ形で書きます。
- `commit`（文字列、必須）: 取るコミット。英小文字の 16 進数 40 桁。
- `resolve`（予約）: この形の版では、書くとエラーです。

2 つの overlay が、どちらの範囲にも入る tag で、同じフォルダか、フォルダとその中のフォルダを埋めることはできません（重なりは `paths` と同じく数えます）。

フォルダは、上流のアーカイブの中に、空で、なければなりません。そうでないと、その版は変換できません。

## オーバーライド

変換したパッケージの `package.json` の欄を直します。オーバーライドには `set` か `merge` が要り、両方を書いてもかまいません。

- `versions`（[範囲](#範囲)、省略可）: 直す版。パッケージの版の範囲です。書かないと、全部の版。
- `set`（オブジェクト、省略可）: `package.json` のいちばん外側の欄と、その値。値（どの JSON の型でも）が、その欄を丸ごと置き換えます。`null` は、その欄を消します。
- `merge`（オブジェクトのオブジェクト、省略可）: `package.json` のいちばん外側の欄ごとに、その欄へ足す鍵と値。欄は、`dependencies` や `vpmDependencies` のようにオブジェクトでなければなりません。
  - 欄にすでにある鍵は、新しい値になります。欄のほかの鍵は残ります。
  - `null` は、その鍵を消します。
  - `package.json` にその欄がないか、`null` のときは、欄を作ります。ただし、`merge` が鍵を 1 つも足さないときは作りません。
  - 欄があって、オブジェクトでないときは、その版は変換できません。
  - 鍵の代わりに `null` や `{}` を書いた欄は、何も変えません。

`set` と `merge` は、`name` と `version` を変えられません。書くとエラーです。

`set` の `vpmDependencies` の値は、値が文字列のオブジェクトか、`null` でなければなりません。`merge` の `vpmDependencies` の下の値は、文字列か `null` でなければなりません。文字列には[置き換え](#置き換え)を書けます。

ある版に当てはまるオーバーライドが複数あると、書いた順に当てます。1 つのオーバーライドの中では、`set` を `merge` より先に当てます。なので 1 つの欄では、最後の `set` が勝ち、そのあとの `merge` が全部足されます。

`package.json` にもとからある欄と鍵は、その位置のままです。新しい欄と鍵は、末尾に足します。1 つの `set` か `merge` の中では、名前のバイト順（大文字が小文字より先）に並べます。何かを変えたとき（`versionFromTag` で版を変えたときも）は、`package.json` の全体を、2 つの空白の字下げで書き直します。改行の形は保ちます。

### 置き換え

`set` と `merge` の `vpmDependencies` の値では、版を変換するときに、次のものを置き換えます。1 つの値に複数書いても、ほかの文字と並べてもかまいません（`">={version} <2.0.0"` のように）。

- `{version}`: このパッケージのこの版（`versionFromTag` で tag の版を取るときは、tag の版）。
- `{dependencies}`: `package.json` の `dependencies` が、鍵と同じ名前のパッケージに書いている値。版に当てはまるオーバーライドを全部当てたあとの値を読みます（`dependencies` を、そのうちのどこで `set` や `merge` しても）。値がなければ、その版は変換できません。
- `{sameTag}`: 鍵と同じ名前のパッケージが、この版を取った tag で持つ版。github のソースだけで、同じソースのほかのパッケージにだけ書けます。パッケージ自身や、ソースにないパッケージを指すとエラーです。その tag に、そのパッケージの版が版の一覧になければ、その版は変換できません。

`vpmDependencies` の値の中の、ほかの `{…}` はエラーです。ほかの場所では置き換えません。`set` と `merge` のほかの値に、`{…}` を文字として書かないでください。のちの形の版で置き換えるかもしれません。

### 依存の辿り方

ALCOM は、`vpmDependencies` の値を版の範囲として読みます。Vpmify も、下の[範囲の書き方](#範囲)で辿ります。`pull` のあと、すべてのレシピの、使える版の全部の `vpmDependencies` を読みます。レシピが出しているパッケージへの依存で、それを満たす使える版がないものについて、Vpmify は次のように版を取ります。

- 依存する側のレシピから先に探し、次に、そのパッケージを出しているほかのレシピを `id` の順に探します。
- `>=` の範囲の下限の版が版の一覧にあれば、その版を取ります。なければ、範囲の中でいちばん新しい版を取ります（プレリリースも含みます）。変換できない版は飛ばします。

Vpmify が範囲として読めない値（`^1.0.0` など）は、そのまま `package.json` に書き、辿りません。

## 版

版は [SemVer 2.0.0](https://semver.org/spec/v2.0.0.html) です。`MAJOR.MINOR.PATCH` に、`-` のあとのプレリリースと、`+` のあとのビルドメタデータを足せます。

- 3 つの数を全部、先頭の 0 なしで書きます。`1.2` や `01.2.3` ではなく `1.2.3`。
- プレリリースとビルドメタデータの識別子は、`0-9`・`A-Z`・`a-z`・`-` でできていて、`.` で区切ります。数字だけのプレリリースの識別子には、先頭の 0 を付けられません（`1.0.0-01` は版ではありません）。ビルドメタデータには付けられます。
- 版は SemVer の順で比べます。ビルドメタデータは比べません。

## 範囲

`tags` と `versions` の値です。

- 比べ方は、演算子と版です: `>=1.2.3`、`>1.2.3`、`<=1.2.3`、`<1.2.3`、`=1.2.3`。版だけなら `=` です。演算子と版のあいだに空白を入れてもかまいません。
- 空白で並べると「かつ」: `>=0.59.0 <0.63.1`
- `||` は「または」: `>=0.33.0 <0.39.0 || >=0.41.0 <0.45.0`
- 書かない範囲、空の文字列、`*` は、全部の版です。
- `^`、`~`、`x` と、数が 3 つない版は書けません。
- プレリリースは、SemVer の順で比べるだけです。`0.125.0-rc.1` は 0.125.0 より前なので、`<0.125.0` に入ります。

## pull が版を選ぶ決まり

- 版を名指ししない `pull` は、選ぶパッケージごとに、`versions` の中の stable の版のうち、変換できるいちばん新しい版を取ります。`pull --prerelease`（GUI では、プレリリースを表示しているとき）は、プレリリースも含めていちばん新しい版を取ります。置き換えを埋められない版は飛ばします。
- そういう `pull` が選んだ版に、[overlay](#overlay) を入れる空のフォルダがないとき（上流のアーカイブを展開して初めて分かります）は、飛ばして古い版を取ることはしません。その `pull` はその版を使える版にせず、警告して、失敗とはせずにほかの版を続けます。そのほかの理由で変換できないときは、エラーです。
- 利用者が版を名指ししたときは、その版だけを取ります。名指ししても、いちばん新しい版を一緒に取ることはしません。
- プレリリースも、利用者が名指ししたときと、[依存](#依存の辿り方)として取るときには取ります。
- 利用者が名指しした版、依存として取る版、使える版を作り直すときの版は、変換できなければエラーです。

## github のソースが版を選ぶ決まり

- tag は版の順に並べます。同じ版の tag は名前の順に並べ、数の続きは値で比べます。値が同じ名前（`r1.0.0` と `r01.0.0`）は、文字の順にします。Git の tag の一覧には日付がないので、この順を古さとして扱います。
- パッケージの同じ版が複数の tag にあるときは、いちばん古い tag から取ります。stable の版は、版がプレリリースでない tag があれば、そのうちいちばん古いものから取ります。ビルドメタデータだけが違う版（`1.0.0+a` と `1.0.0+b`）は、ALCOM と同じく、ここでも同じ版です。
- パッケージの版を取る tag と同じ版に読める tag が、パッケージの同じ版を持つときは、Vpmify が警告します。見分ける `tagVersion` を書いてください。`tagVersion` がなくても、リポジトリに `v1.2.3` と `1.2.3` の両方があると起きます。パッケージの版をより古い tag から取るときは、同じ版に読める tag があっても警告しません。tag `1.2.2`・`1.2.3`・`v1.2.3` がどれもパッケージの 2.0.0 を持つと、`1.2.2` から取り、警告は出ません。
- `{sameTag}` は、版を取った tag での、ほかのパッケージの版を指します。
